### Table `waitlist_events` (`packages/db/src/schema/waitlist-events.ts`, D240)

One audit row per change to an entry, written in the same transaction as the change. It contains no email, so it is kept when its entry is pruned.

| Column | Type | Null | Notes |
|--------|------|------|-------|
| `id` | uuid | no | PK, `gen_random_uuid()` |
| `entry_id` | uuid | no | the entry's id; **no FK**, so the row survives the prune |
| `action` | `waitlist_event_action` | no | |
| `actor_id` | uuid | yes | FK `users(id)` `ON DELETE SET NULL`; the admin for `invited`, `invite_resent` and `removed` (032), null for visitor actions |
| `source` | `waitlist_source` | yes | for `created` and `resent` |
| `created_at` | timestamptz(3) | no | `now()` |

Index `waitlist_events_entry_idx (entry_id, created_at)` for "history of one entry"; `waitlist_events_created_idx (created_at)` for counts per window. No updates, no deletes from code.

## State transitions

```text
            join (new)                 confirm link              invite (032)
  (none) ─────────────▶ pending ───────────────────▶ confirmed ─────────────▶ invited ──(first sign-in)──▶ "joined" (view only)
                          │  ▲ join again: new token        │                     │
                          │  └──────────────────────────────┘ (no change, no mail)│
                          └──────────────┬───────────────────┴─────────────────────┘
                                         ▼ remove (032)
                                      removed ──(30 days)──▶ deleted (prune)
  pending ──(confirm expired + 30 days)──▶ deleted (prune)
```

| From | Event | To | Writer |
|------|-------|----|--------|
| — | join (no live entry, no user) | `pending` | `waitlist.service.join` |
| `pending` | join again | `pending` (new token; kind/note/utm updated when source is `landing`) | `join` |
| `pending` | confirm within TTL | `confirmed` | `waitlist.service.confirm` |
| `confirmed` | admin invite | `invited` | 032 via `waitlist.service.markInvited` |
| any but `removed` | admin remove | `removed` | 032 via `waitlist.service.remove` |
| `pending` (expired + 30 d), `removed` (+ 30 d) | weekly prune | deleted | `prune-waitlist` job |
