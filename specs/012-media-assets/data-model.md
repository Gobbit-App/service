# Data Model: Media assets

One new table and enum, one partial index on `items`, and one additive payload change. Migration `0012_media_assets` (generated by `pnpm db:generate`, plus hand-written backfill SQL) and `migrations/down/0012_media_assets.sql`.

## `asset_source` (enum, new)

`editor` | `ingest` | `link_snapshot` | `remote`

- `editor`: browser upload signed by D133 and confirmed by D157.
- `ingest`: a server-side upload from a share (Phase 5).
- `link_snapshot`: a preview image copied by [`014-link-snapshots`](../014-link-snapshots/data-model.md).
- `remote`: `uploadFromUrl` for any other caller (Phase 13 MCP).

## `assets` (new)

| Column | Type | Null | Notes |
|--------|------|------|-------|
| `id` | uuid PK | no | `gen_random_uuid()` |
| `deck_id` | uuid FK → `decks.id` `ON DELETE CASCADE` | no | Deleting a deck drops its rows. `decks.service` deletes the deck's storage folders after commit (`media.deleteForDeck`, by the `gobbit/{items,ingest,links}/<deckId>/` prefixes). The deck UUID makes these prefixes unique across environments |
| `public_id` | text | no | **UNIQUE**; the Cloudinary public id, e.g. `gobbit/items/<deckId>/abc123` |
| `source` | `asset_source` | no | |
| `width` | integer | yes | CHECK `> 0`; null for backfilled rows |
| `height` | integer | yes | CHECK `> 0` |
| `bytes` | integer | yes | CHECK `>= 0` |
| `format` | text | yes | `jpg`, `png`, `webp`, `heic`, … as reported by Cloudinary |
| `uploaded_by` | uuid FK → `users.id` `ON DELETE SET NULL` | yes | null for backfill and system snapshots |
| `created_at` | timestamptz(3) | no | default `now()`; the grace period counts from here |

Indexes:
- `assets_public_id_key` (unique);
- `assets_created_at_idx` on `created_at` (sweep candidates);
- `assets_deck_id_idx`.

No `updated_at`: rows are inserted and deleted, never edited. An upsert on confirm only fills null dimensions.

## `items` index (new)

`items_image_public_id_idx` on `((payload->>'publicId')) WHERE type = 'image'`, partial, for the sweep's anti-join and the D160 lookup. 014 adds the matching index for link previews.

## Orphan query (D158)

```sql
SELECT a.id, a.public_id
FROM assets a
WHERE a.created_at < now() - make_interval(days => $grace)
  AND NOT EXISTS (
    SELECT 1 FROM items i
    WHERE i.type = 'image' AND i.payload->>'publicId' = a.public_id
  )
  -- 014 adds: OR (i.type = 'link' AND i.payload #>> '{preview,publicId}' = a.public_id)
ORDER BY a.created_at
LIMIT $batch;
```

Every item status counts as a reference: proposed, published, archived, and soft-deleted rows still in the 30-day window. A row stops referencing an image only when its payload changes or the purge (D132) deletes it.

## Payload change (`packages/shared/src/schemas/payloads.ts`)

| Type | Before | After |
|------|--------|-------|
| `image` | `{ publicId, alt }` strict | `{ publicId, alt, width?: int 1..20000, height?: int 1..20000 }` strict; `width` and `height` are server-owned (D160) |

The payload size CHECK (≤ 8192 bytes) is unaffected. `item_search_text()` already drops `publicId` for images, and the two new fields are numbers, so search text doesn't change.
